Teaching the Cheap Gauge

Semantic Entropy works by asking the model ten times. A probe learns to guess its answer from one. This is the walk from one to the other — and specifically, what those (hidden state → SE value) pairs actually are.

Four tools, three questions

Before the mechanism, the place SEP occupies. Sort these by what each one asks and the confusion resolves: SEP is not a fourth question. It is a second way of answering the third.

Stage 1 — the expensive measurement

What SE does, per question

Four steps, run once per prompt. Every one of them costs something, and together they are the reason a cheaper route is worth building.

01

Sample N answers

Ask the same question ten times at temperature > 0. One request with n=10 — the prompt is prefilled once and the ten continuations decode as a batch.

s₁ … s₁₀ ~ p(· | x)
02

Test pairs for equivalence

A separate NLI model judges whether two answers mean the same thing — entailment required in both directions, so "Paris" doesn't merge with the vaguer "somewhere in Europe".

equiv(a,b) ⟺ NLI(a,b)=entail AND NLI(b,a)=entail
03

Cluster by meaning

Walk the answers, dropping each into the first cluster whose representative it matches, or opening a new one. Ten strings collapse into K distinct claims.

C₁ … C_K p(C_k) = |C_k| / N
04

Entropy over the clusters

Shannon entropy of the cluster-size distribution. All ten in one cluster → 0 nats, the model is committed. Ten singletons → log 10 = 2.303, it is confabulating.

SE = −Σ p(C_k) · log p(C_k) 0 ≤ SE ≤ log N

A note on the unit: what is a "nat"?

Entropy answers "how uncertain?", and the answer is a number of something — the way a distance is a number of metres. Which unit you get depends only on which logarithm you use: log₂ gives bits, natural log gives nats. The code calls np.log, so these numbers are nats. Same quantity, different ruler.

Nats have no everyday intuition attached, so don't try to feel the unit — read positions on the scale instead:

So SE = 1.973 is not a mysterious quantity — it is simply near the top of a 0 to 2.303 scale, meaning the ten answers fragmented badly. And "a regressor predicting SE in nats" unpacks to: a thing that outputs a number on this same scale, rather than a yes/no label. Which is exactly why it can reuse SE's threshold without recalibration.

Stage 3 — the fit

500 rows become 3585 numbers

Now it is ordinary linear regression. Find the weight vector that best predicts the amber column from the cyan column — in this implementation, ridge regression, which is least-squares with a penalty on large weights to stop 3584 dimensions from overfitting 500 rows.

# eval/train_sep_probe.py — the fit, in full
X = np.stack(hidden_states)      # [500, 3584]  the cyan column
y = np.asarray(se_labels)        # [500]        the amber column

ridge = Ridge(alpha=1.0)
ridge.fit(X, y)                  # ← the entire "training"

probe.linear.weight.copy_(...)   # 3584 weights
probe.linear.bias.copy_(...)     # + 1 bias
torch.save(probe.state_dict(), output_path)

No gradient descent, no epochs, no GPU. A closed-form least-squares solve over a 500×3584 matrix — seconds of CPU. The expensive part was building X and y in the first place: 500 prompts × (10 generations + ~80 NLI passes) each.

Stage 4 — runtime

What actually happens per request

The saved file is 3585 floats. At serving time the two paths diverge completely.

SE · the teacher

Ten generations, then clustering

  • Sample N=10 from the model
  • ~80 NLI forward passes, sequentially
  • Cluster, then take entropy of the sizes
  • A second model resident in VRAM

≈10× compute · latency dominated by NLI

SEP · the student

One dot product

  • Read the pooled hidden state you already computed
  • Multiply by 3584 weights, add a bias
  • That number is the score, in nats
  • No second model, no extra generations

SE = w·h + b · sub-millisecond

Because the probe was fit against SE in nats, its output lands on the same scale as SE. The threshold carries over unchanged — SEP drops into the escalation comparator wherever SE sat, with no recalibration of se_threshold. That is a deliberate implementation choice: a regressor, not a classifier.

Why this works at all

The claim underneath SEP is genuinely surprising, and worth stating plainly: the model's hidden state, taken over the prompt alone and before any answer exists, already encodes whether it is about to confabulate.

Predictive entropy fails at exactly this because it reads the output distribution — how confidently the words were chosen. A fluent lie has confident tokens. The hidden state is a different place to look, and the information is apparently sitting there, linearly decodable, the whole time. A single nn.Linear is enough to pull it out.

What you give up

  1. White-box access is mandatory. You must be able to read hidden states. No vendor API exposes them, so this only works on a model you serve yourself — disqualifying for most teams before any other consideration.
  2. The probe is per-model. Weights fit on one backbone are meaningless on another; the code raises on a dimension mismatch rather than silently scoring nonsense. Retrain on every model change.
  3. It approximates. SEP inherits every one of SE's failure modes, then adds its own prediction error. Where the linear assumption breaks — adversarial or out-of-distribution prompts — it degrades quietly.
  4. SE does not go away. You need it to produce the labels, and to re-check periodically that the probe hasn't drifted. SE moves from the hot path to the calibration bench; it does not get deleted.

The teacher is not replaced. It is moved off the hot path and kept for calibration.
